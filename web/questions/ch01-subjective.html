Ngân Hàng Câu Hỏi Tự Luận & Barem Điểm: Chương 1

🎯 Mục tiêu: Rèn luyện kỹ năng trả lời tự luận chuẩn barem chấm UIT Nguồn: Đề thi Giữa kỳ 2018–2025

Học phần tự luận đòi hỏi sinh viên trả lời đúng và đủ các từ khóa bắt buộc (Key Points) theo barem chấm điểm của giảng viên. Hãy thử sức với các bài tập tự luyện tương tác dưới đây:

1. Thẻ Ghi Nhớ Tự Học (Active Recall)

Chương 1 · Lệnh đặc quyền Mức độ: Quan trọng ⭐⭐⭐
Tại sao hệ điều hành cần Chế độ hoạt động kép (Dual-Mode)? Phân biệt User Mode và Kernel Mode qua Mode bit. Nêu 4 ví dụ về lệnh đặc quyền.
💡 Gợi ý: Hãy nghĩ về việc điều gì sẽ xảy ra nếu một chương trình người dùng thực thi lệnh tắt ngắt CPU (cli) hoặc ghi đè bảng vector ngắt.
🔑 Các ý bắt buộc (Key Points):
  • Mục đích: Bảo vệ tài nguyên phần cứng, cách ly lỗi chương trình.
  • Mode bit: 0 (Kernel Mode), 1 (User Mode).
  • Lệnh đặc quyền (Privileged): Tắt/bật ngắt, đổi Mode bit, lệnh I/O trực tiếp, nạp thanh ghi base/limit.
📖 Lời giải hoàn chỉnh:

Hệ điều hành cần Dual-Mode để bảo vệ CPU, bộ nhớ và các thiết bị khỏi sự phá hoại hoặc lỗi từ ứng dụng người dùng. Phần cứng CPU cung cấp bit trạng thái gọi là Mode bit (0: Kernel Mode, 1: User Mode). Chương trình User Mode bị cấm thực thi trực tiếp các lệnh đặc quyền (như tắt ngắt cli, đổi mode bit, thao tác I/O). Muốn dùng tài nguyên, ứng dụng phải gọi System Call để chuyển quyền sang Kernel xử lý.

2. Khung Tự Luyện & Tự Chấm Điểm (Subjective Practice)

Bài Tập Tự Luyện: So Sánh Đa Chương và Chia Sẻ Thời Gian (1.5 điểm)

Tự luận · Giữa kỳ

Đề bài: So sánh Hệ thống Đa chương (Multiprogramming) và Hệ thống Chia sẻ thời gian (Time-Sharing / Multitasking) theo 3 tiêu chí: Mục tiêu thiết kế chính, Cơ chế điều phối CPU, và Khả năng tương tác với người dùng.

Tự chấm trung thực để củng cố kiến thức

📋 Barem Chấm Điểm Chính Thức (Tự Đánh Dấu):

[0.5 điểm] Mục tiêu thiết kế:

Nêu đúng: Đa chương nhằm tối đa hóa hiệu suất CPU (Maximize CPU utilization); Chia sẻ thời gian nhằm tối thiểu hóa thời gian đáp ứng (Minimize Response Time).

[0.5 điểm] Cơ chế điều phối CPU:

Nêu đúng: Đa chương chuyển CPU khi tiến trình hiện tại chờ I/O hoặc kết thúc; Chia sẻ thời gian luân chuyển CPU theo lượng tử thời gian (Time Quantum) cực nhỏ nhờ ngắt đồng hồ (Timer).

[0.5 điểm] Khả năng tương tác người dùng:

Nêu đúng: Đa chương khả năng tương tác rất thấp (hệ thống theo lô Batch); Chia sẻ thời gian khả năng tương tác trực tiếp rất cao theo thời gian thực.

Điểm số tự đánh giá của bạn: 0.00 / 1.50 điểm
